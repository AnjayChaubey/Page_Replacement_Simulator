Welcome to the Operating Systems Page Replacement Simulator

In modern virtual memory systems, operating systems utilize paging to allow processes to execute with physical memory smaller than their address space. When a requested page is not currently in physical RAM, a Page Fault is triggered, requiring a Page Replacement Algorithm to choose a victim frame. This simulator models, animates, and mathematically benchmarks all major replacement algorithms powered directly by a native C++17 calculation engine.

Belady's Anomaly Laboratory

Belady's Anomaly is the counter-intuitive phenomenon wherein increasing the physical memory allocated to a process (more frames) results in an INCREASE in the number of page faults!
This anomaly can occur in non-stack algorithms like FIFO. Stack algorithms such as LRU and Optimal are mathematically guaranteed never to exhibit Belady's Anomaly because the set of pages in memory for $m$ frames is always a strict subset of the pages in memory for $m+1$ frames ($M(m) \subseteq M(m+1)$).

Operating Systems Algorithm Learning Center

Comprehensive educational guide for undergraduate Operating Systems students covering the theory, mechanics, mathematical properties, and real-world implementation tradeoffs of virtual memory page replacement algorithms.

1. FIFO (First-In, First-Out)

Simplest Queue-based Page Replacement Policy
FIFO
Working Principle

Replaces the page that has resided in physical memory the longest. Maintains a FIFO queue of allocated frames. When a page fault occurs and all frames are occupied, the page at the head of the queue is evicted.

Time & Space Complexity

Replacement Time: $O(1)$ constant time queue pop.
Lookup Time: $O(1)$ with hash map or page table.
Space Overhead: Low ($O(F)$ queue storage).

Real-World Relevance

Rarely used alone in modern operating systems due to poor performance on cyclic workloads and vulnerability to Belady's Anomaly, but widely used as a baseline benchmark.

Advantages & Trade-offs

✓ Pros: Trivial to implement, negligible hardware overhead, predictable eviction order.

✗ Cons: Ignores frequency and recency of accesses; frequently used pages are evicted simply because they arrived early; exhibits Belady's Anomaly.

Deterministic Tie-Breaker

Strict monotonically increasing arrival sequence order.

2. LRU (Least Recently Used)

Temporal Locality Approximation Policy (Stack Algorithm)
LRU
Working Principle

Evicts the page that has not been referenced for the longest duration of time. By exploiting temporal locality (recently accessed data is likely to be accessed again soon), LRU closely mimics the Optimal benchmark without requiring future knowledge.

Time & Space Complexity

True LRU: $O(1)$ eviction and update using a doubly linked list + hash map, or hardware counter/timestamp registers per page.
Immunity: Belady's Anomaly immune (Stack Algorithm).

Real-World Relevance

Core inspiration for modern multi-queue cache eviction policies (e.g., Linux page cache 2-list active/inactive LRU, Redis LRU, database buffer pools).

Advantages & Trade-offs

✓ Pros: Excellent hit ratio in typical programs with locality; guaranteed immune to Belady's Anomaly.

✗ Cons: Pure hardware LRU is expensive because every memory read/write must update timestamps or list pointers; vulnerable to sequential streaming scans.

3. OPTIMAL (Belady's MIN Algorithm)

Theoretical Offline Lower Bound Benchmark
OPTIMAL
Working Principle

Replaces the page whose next reference occurs farthest in the future (or never). Requires complete omniscient knowledge of the future reference string.

Mathematical Optimality

Mathematically proven to produce the absolute lowest number of page faults possible for any fixed number of frames. Belongs to the stack algorithm family.

Theoretical Status

Cannot be implemented in real general-purpose online operating systems because future memory accesses cannot be predicted in advance. It exists solely as an ideal baseline for evaluating practical algorithms.

Deterministic Tie-Breaker

Pages never referenced again are prioritized for eviction. Among ties, FIFO arrival order is used.

Analytical Purpose

Measures how close an online heuristic (e.g. LRU or Clock) comes to the theoretical limit for a given workload trace.

4. LFU (Least Frequently Used)

Frequency-Counting Eviction Policy
LFU
Working Principle

Tracks how many times each resident page has been accessed while in physical memory. When replacement is required, the frame with the lowest access counter is replaced.

Deterministic Tie-Breaker Policy

LRU Tie-Breaker: If multiple candidate frames share the identical minimum frequency counter, the page that was least recently used is evicted.

Cache Pollution & Aging

A page heavily accessed during program startup may retain high counters and linger in memory long after it is no longer needed unless frequency aging (decay) is implemented.

Advantages & Trade-offs

✓ Pros: Retains high-demand global working set pages effective in static distribution workloads.

✗ Cons: Slow to adapt to phase shifts; newly referenced pages start with low counter (1) and risk immediate premature eviction.

5. Second Chance (Clock Algorithm)

Hardware-Efficient Circular LRU Approximation
SECOND CHANCE
Working Principle

Arranges memory frames in a circular buffer with a scanning pointer (the "Clock Hand"). Each frame has a single 1-bit reference bit set by MMU hardware on each memory access.

When a page fault requires replacement, the clock hand advances circularly. If it encounters a frame with reference bit 1, it clears the bit to 0 ("second chance") and advances. If it encounters a frame with bit 0, that frame is evicted immediately.

Real-World Relevance

Because hardware only needs to set 1 bit per page access, the Clock algorithm and its two-handed variants (e.g. BSD Clock, Linux page aging) form the practical core of production virtual memory managers.

Advantages & Trade-offs

✓ Pros: Extremely fast $O(1)$ amortized replacement, negligible hardware overhead (1 bit per frame), closely approximates LRU performance.

✗ Cons: In worst-case degenerate cycles with all bits 1, the hand must traverse all frames before finding a victim.
